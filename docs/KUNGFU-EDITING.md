# 功法编辑（0.4.30.1）

## 自创功法的原生处理逻辑

检查对象为本机 `GameAssembly.dll` 和对应 IL2CPP 元数据。九类功法共用定义和等级数据，但载入、装备、突破效果分配及战斗动作存在类别分支：

| 类别 | 装备位置 | 原版载入时的目标及动作 |
| --- | --- | --- |
| 内功（0） | 内功槽 | 自身；范围 0；`cure`；“真气喷”特效 |
| 轻功（1） | 轻功槽 | 跳跃；范围按稀有度生成；`jump_big`；“紫圈”特效 |
| 绝技（2） | 绝技槽 | 自身；范围 0；`skill0_2`；“护盾”特效 |
| 拳掌、剑法、刀法、长兵、奇门、射术（3–8） | 攻击栏 | 使用各自原版目标、范围、动作、弹道和特效 |

自创功法从已载入的原版定义复制，因此必须保留这些已生成的数据。基础页选择总母版后，点击“将总母版复制到全部元素”，会同步类别、目标和十五项来源；单独选择一项来源只改变该项。手动跨类别组合时，仍需自行选择匹配的目标、范围和动作。

五组数据分工：威力表参与伤害计算；需求表用于修炼条件；升级表在后续升级时永久改变角色属性；装备表参与运功后的角色总加成；使用表用于施放效果。前三类的突破数据加入装备效果，攻击类的突破数据加入使用效果。它们不能只靠替换一张效果表处理。

保存前把候选配置序列化、重新读取并重建其中所有定义，成功后才覆盖正式文件。保存后的注册与角色刷新错误会传回编辑器，明确区分“未写入定义”和“定义已保存但后续处理失败”。临时测试插件仅用于本机隔离检查，不包含在分发包中；完整原生遍历测试目前等待游戏退出后执行，不能据模拟检查声称全部实测通过。

## 使用与持久化

在藏经阁／书房打开“自创功法”，点击基础页的“载入原版功法编辑”，或保存／管理页的“编辑原版功法（全部九类）”。搜索名称或 ID，点选并确认载入，再编辑参数、效果、范围、姿态、动作、弹道与图标，最后保存。已保存的原版修改和自创功法均可从保存／管理页重新载入。

支持内功、轻功、绝技、拳掌、剑法、刀法、长兵、奇门、射术。原版编辑沿用原 ID，对所有使用该功法的角色生效；新建自创功法仍使用 900000–999999 的独立 ID。内功、轻功、绝技使用各自的原生装备槽，其他功法使用攻击栏；试战入口也接受前三类装备。

保存会重算技能的装备与使用效果、四种效果消耗、角色总加成，并刷新图标。等级、经验、突破词条、当前技能槽和装备记录保持原值。更换功法类别时，须先卸下该功法，保存后再按新类别装备。升级效果仍按原生规则在后续升级时获得，不回溯改写已经获得的永久属性。

定义保存在 `BepInEx/config/LongYinTrainer.custom-kungfu.json`；每次保存自动保留 `.bak`。旧 Schema 5 的自创记录可直接读取，保存后写为 Schema 6；新增 `EditOriginal` 标记区分原版覆盖和自创记录。不要用旧版修改器重新保存包含原版覆盖的配置。停用模组后原版定义恢复；已经发生的属性升级、秘籍添加等存档变化不会自动撤销。

实现检查基于本机游戏的 IL2CPP 元数据与原生方法反汇编：九类功法共用 `KungfuSkillData` 和 `KungfuSkillLvData`。`HeroData.EquipSkill` 将类别 0、1、2 分别放入内功、轻功、绝技槽；`CountHeroData` 独立读取三个槽和攻击栏。`ResetSpeEquipData`、`ResetSpeUseData` 按类别处理突破数据并重算效果消耗，空效果表会提前返回，因此调用前须清零旧消耗。旧实现仅赋值效果表，遗漏了这些衍生缓存和角色总加成。

回归命令：

```powershell
dotnet run --project KungfuRegression/KungfuRegression.csproj -c Release
```

34 项模拟检查覆盖九类、独立槽、空效果残留消耗、不同实例与重复指针、读档失效、失败重试、原版 ID 0、原始来源快照和数据库替换、类别变更保护。测试编译并执行生产刷新与原版编辑代码，模拟原生 API；它们不代替游戏内逐项实测。
