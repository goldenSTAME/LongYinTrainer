# 手动移除或恢复功法

适用版本：0.4.30.17。先退出游戏，备份游戏存档，以及整个 `BepInEx/config` 文件夹。下面只删除指定记录，不要删除整个功法配置文件或直接卸载插件。

## 先确认是哪种记录

打开 `BepInEx/config/LongYinTrainer.custom-kungfu.json`，在顶层 `Skills` 数组里按 `Name` 和 `Id` 找到目标。编辑器显示的 ID 可用于核对。不要只按相似名称删除。

- `EditOriginal: true`：覆盖原版功法。删除这条覆盖记录后，重启游戏会恢复原版定义；原版技能 ID 继续存在。
- 自创 ID 900000–999999、`EditOriginal` 为 false：新增功法。删除定义会让仍引用这个 ID 的技能、秘籍失去定义。

## 恢复一门被编辑的原版功法

1. 在退出游戏并备份后，用文本编辑器打开上述 JSON。
2. 仅删除 `Skills` 中目标 ID 的完整对象，注意对象之间的逗号。保留其他对象及顶层字段。
3. 保存为 UTF-8，检查 JSON 语法，再启动游戏。原版定义应恢复。
4. 查看角色属性与功法说明，确认无误后另存一个存档。已经通过升级获得的永久属性不会随配置回退自动恢复。

## 删除尚未使用的自创功法

仅适用于确认任何角色都没有习得、任何背包/仓库/藏经阁等位置也没有对应秘籍的情况。

1. 保留插件及原配置，先在游戏内检查目标是否仍有引用。只卸下技能不等于遗忘，丢弃秘籍也不会删除已学记录。
2. 如果确认从未习得、从未生成秘籍，退出游戏后，按上述方式仅删除该 ID 的完整配置对象。
3. 重启，确认配置正常加载后再继续游戏。保留备份，暂时不要删除。

如果已经生成秘籍，必须先用游戏提供的物品处理功能移除所有对应秘籍，并保存；不要卖给 NPC 当作彻底删除，因为它可能仍存在于世界存档中。不确定其他角色、仓库或商店是否持有时，保留定义，或恢复生成前的存档。

## 已经学会的自创功法

当前版本没有“已学功法管理/遗忘”按钮，该功能已按要求撤回。不能仅靠手动删除配置安全移除已学功法。

最稳妥的手动回退方式是：恢复习得和生成秘籍之前的存档，再退出游戏，删除对应配置条目。如果没有这样的存档，暂时保留定义并卸下有问题的功法；需要针对存档另做清理，不能用删除配置代替。

不要直接在存档中搜索 ID 后整段删除：装备记录中有些字段保存的是已学列表索引，不是功法 ID；删掉一项后其他索引也必须正确调整，还涉及其他角色、当前技能及秘籍引用。现有孤立引用清理主要针对中断试战遗留，不保证清除所有仓库、秘籍、临时角色或回退属性。

## 已经误删后报错

1. 停止覆盖原存档，退出游戏。
2. 恢复删除前备份的 `LongYinTrainer.custom-kungfu.json`；也可使用同目录 `.bak`，但应先核对它确实包含目标 ID，且对应正确版本。
3. 保持兼容版本插件启用，再载入删除前的存档。
4. 仍无法载入时，保留 `BepInEx/LogOutput.log` 和游戏 `Player.log`，连同发生步骤排查。不要反复删除其他定义或覆盖唯一备份。

此说明基于代码检查，不代表自创功法闪退已经修复，也不能保证任意已经损坏的存档可恢复。

## 0.4.30.18：界面删除自定义内容

在藏经阁自创功法的“保存／管理”页，从列表载入目标，再回到此页点击“删除当前自定义内容（保留存档兼容 ID）”，核对名称和 ID 后再次点击确认。战斗中不可执行。

此操作删除自定义参数/效果/动作配置，以同类原版母版恢复定义，保留 RemovedContent=true 的兼容记录与原 ID，避免已学技能和秘籍失去定义。列表会标注“已删除”，并非从角色已学列表遗忘，也不会回退历史升级属性。原版覆盖记录恢复原版定义。配置写入前会验证并备份 .bak；请另存游戏、保留备份。兼容记录不可继续保存编辑，可新建功法或恢复备份。

注册单条异常会记录功法 ID/名称并继续后续条目；同类原版母版有效时尝试会话内回退，原异常配置不自动覆盖。母版也无效、原生进程崩溃、存档已损坏等情况不能保证恢复。收到的旧日志仅显示 0.4.30 载入两条配置及构造补丁警告，没有崩溃堆栈；本次仅编译核验，未实测该用户存档。

### 0.4.30.19 显示修正

已删除记录不再显示于保存管理列表或自创秘笈生成目录；分页只统计未删除记录，空列表显示“暂无已保存功法”。按钮简化为“删除当前功法”，只在载入有效已保存功法时显示。删除后切换为空白草稿，不再选中兼容记录。以前已经删除的记录也会自动隐藏。后台保留 ID 的机制不变，不会自动遗忘角色已学技能或移除既有秘籍。
